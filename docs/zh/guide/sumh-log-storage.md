# SUMHP 日志保留与重复消息

第三十七批在当前源码中实现日志大小控制、重复 Warning/Error 汇总和后台标准流隔离。它只作用于 SUMHP 的结构化日志；SUMH 内核日志、其他 ksud 日志、Android logcat 和诊断导出各有独立范围。主机检查及 ARM64 构建结果见[第三十七批记录](../../plans/SUMH-implementation-validation-batch37-2026-10-19.md)。第四十一批补 Manager 清空入口的文件校验、非阻塞争锁及错误传播，见[第四十一批记录](../../plans/SUMH-implementation-validation-batch41-2026-10-19.md)；设备、断电和性能验收单独进行。

## 存储范围

运行目录由控制器决定，当前日志为 `/data/adb/ksu/log/sumhp.log`。以下名称均相对于实际日志路径；不要将示例路径作为删除其他文件的依据。

| 文件 | 当前行为 |
| --- | --- |
| `sumhp.log` | 当前日志，成功维护后最多 1 MiB。追加一条消息将越界时，先保留末尾最多 512 KiB 范围内完整的 LF 分隔记录，再写保留提示和新消息。 |
| `sumhp.log.old` | 上次启动留下的历史，成功维护后最多 1 MiB。相同启动内裁剪当前日志不会覆盖它；跨启动轮转会替换上一份历史。 |
| `sumhp.log.stage` | 固定的私有暂存文件，裁剪和 boot marker 写入共用，最多 1 MiB。持锁时只回收这个精确名称；发现链接或非普通文件则拒绝继续。 |
| `sumhp.log.boot`、`sumhp.log.lock` | 启动轮转记录与协作锁。有效 marker 小于 256 字节；锁内容不用作日志。不按文件内容清空其他资源。 |

当前、历史及暂存三个路径的受管内容在维护成功后合计不超过 3 MiB，另有很小的 marker 和锁。**这不是整个目录或设备的磁盘占用上限**：不包括文件系统元数据、仍被其他读者打开的旧 inode、外部写入、其他日志和既有备份。旧版本留下的超大文件只有在维护成功后才进入上限；维护失败时停止本次追加，不能声称旧文件已经缩小。

裁剪只拷贝有限尾部，丢弃首尾不完整记录并留下 `[WARN] [logging]` 保留提示。某一条旧记录超过尾部窗口时，可能没有完整旧记录可保留。Manager 仍只读取当前日志尾部最多 256 KiB、1,000 行，不因此自动展示全部 1 MiB 或 `.old`。

目录继续使用原有私有目录保护；日志、历史、锁、marker 和暂存文件检查普通文件/单链接并恢复为 0600。替换在共用锁内完成，暂存写完并同步、关闭、rename 后同步父目录；rename 后同步失败不伪装成回滚，停止本次追加，下次调用重新核对。普通追加不逐条 fsync，突然掉电可能丢失最后几行。跨启动先处理既有 P/R 轮转状态，再裁剪，避免将新启动日志误当作旧日志覆盖历史。

## 重复消息如何显示

只对同一进程内、相同等级、相同组件和相同**编码截断后文本**的 Warning/Error 汇总。首次立即写入；后续相同事件累积计数，在下次同类事件到达且窗口满 30 秒、条目被淘汰或正常关闭刷新时，输出 `[repeated N times]`。N 不包含首次单独显示的记录；饱和计数显示 `at least`。计数写入失败会保留待汇总信息。

最多保留 32 个最近使用的身份，无定时线程或定期唤醒。30 秒是单调时钟窗口，不保证第 30 秒自动出现汇总；时间不可用或倒退时尝试排出已有汇总，并直接记录当前消息。等级、组件或文本不同的消息立即可见。Info 直接写入；Debug 沿用已有 debug/verbose 设置，关闭时不访问日志文件。

组件最多 256 字节、正文最多 8,192 字节，计入截断提示；保留完整有效 UTF-8 字符，换行和回车转义，无效字节和部分控制字符替换为 `?`。汇总计数位于正文前端，最长消息的末尾仍可能截断。此编码不属于隐私脱敏，路径或模块名称仍可能出现。

这不是所有进程共用的频率限制；变化的文本、短命 CLI 和外部写入仍可能产生较多记录。进程/启动变化、当前文件身份、大小或修改时间变化会重置本进程的汇总状态，外部写入和用户清空也在此范围。异常退出或重置可能丢失尚未落盘的重复计数，不能拿汇总数充当完整操作审计。

后台 daemon 的 stdin/stdout/stderr 连接到 `/dev/null`，避免原始输出绕过容量控制或长期占有被替换的日志 inode。已明确处理的启动错误经结构化 logger 记录；foreground serve 的 stderr 和命令结果捕获继续保留。未经过 logger 的后台原始输出不会被保存到本日志。

## 使用步骤、失败处理与撤销

**目的与条件：** 在包含第三十七批控制器的设备上检查近期错误与保留范围。只查看自己有权访问的日志；主机测试不能证明设备已运行该版本。

1. 打开 Manager → SUMH → 日志，选择守护进程并手动刷新。阅读与筛选见[场景 28](sumh-usage-scenarios.md#28-保持阅读位置并检查最新日志当前源码已实现)。
2. 看到保留提示时，将当前页面理解为保留下来的尾部。看到重复汇总时，同时核对首次记录、组件和等级；多条原始事件可能只占一条汇总记录。
3. 需要跨启动证据时，通过已有授权的本地工具读取实际路径的 `.old`，记录组件版本、boot ID 与采样时间。不要仅为查看历史而启动恢复或重建规则。
4. 分享原始日志前自行检查并删除不应外发的路径、模块名和设备信息。四场景的[私有诊断包](sumh-diagnostic-packages.md)已有默认脱敏、完整预览、导出和条件删除；该入口不会自动将原始日志、doctor 或全量 bugreport 改为脱敏，也不自动上传。

**期望观察：** 持续追加不会使由本 logger 成功维护的当前路径无限增长；首次不同错误可见，重复计数按上述条件出现；同启动裁剪保留 `.old`。这些只是日志观察，运行状态仍由状态查询及对应观察者验证。

**失败处理：** 权限、空间、类型、短写或同步失败会使写入停止；原始错误可能只在前台 stderr 可见，后台兜底 stderr 被丢弃，所以日志沉默不证明正常。未知/损坏 marker 被保留并拒绝写入，不自动重置。检查实际路径、可用空间和组件版本，保留异常文件供排查；不要盲删锁、marker 或替换正在使用的文件。Manager 清空按钮不能修复 marker/type 问题。

**撤销：** 关闭筛选/跟随只改变阅读状态。Manager 的确认清空仅截断当前守护进程日志，保留历史、marker、配置和规则；清除历史无法由软件恢复，先保留必要证据。下一次观察到清空后，同类错误会作为首次记录重新显示。包含第四十一批改动的 Manager 在清空前检查已打开文件的单链接、普通文件及非负大小，拒绝异常文件；详细步骤和限制见下节。存储上限和汇总参数目前是编译常量，没有新增可调命令；不会用全局规则 clear 撤销日志操作。

## 清空当前守护进程日志

**目的与条件：** 主动清除当前 SUMHP 日志内容。使用包含第四十一批改动的 Manager，并先保留需要的原始证据。清空不能撤销，历史 `.old`、marker、暂存文件、配置和规则保留。

1. 在 Manager → SUMH → 日志中选择守护进程，手动刷新并核对内容。内核日志没有此清空入口。
2. 点击清空并确认。入口先取得同一个 `.lock` 的独占锁，再检查和截断当前文件；不创建缺失的日志，不替换路径，也不删除其他文件。
3. 成功后页面请求刷新。取得合法锁后确认当前日志不存在时，返回成功且不创建日志；日志写入器在清空后仍可追加，因此刷新不保证永远为空。
4. 显示现有“操作失败”提示时，先手动刷新并保留现场。占锁、权限、类型/链接检查及 IO 都可能导致失败；UI 目前不逐项区分。确认写入器恢复后可重新发起并确认，不自动循环重试。异常链接、marker 或类型需要单独排查，不能用清空修复。

当前文件和锁都通过 `O_NOFOLLOW` / `O_NONBLOCK` 打开，检查实际描述符的普通文件类型、恰好一个硬链接及非负大小；系统调用失败保留原始错误，结构不符返回 EINVAL。`LOCK_NB` 使占锁时在打开当前日志之前失败；合法的锁和日志在使用时收紧为 0600。任何前置校验或权限调整失败都不会进入截断。

这是协作锁约定：写入器和清空入口共同维护稳定的锁文件，操作期间持锁；不承诺阻止另一个不遵守约定的高权限进程替换锁、改动祖先目录或在检查之后创建硬链接。非阻塞打开和争锁也不是整条 JNI 调用的截止期限，root 授权、共享 worker 及其他文件系统调用仍有各自的等待边界。

清空不执行 fsync，不承诺断电耐久性。失败也不表示此前已收紧的权限被回滚；已清除内容没有软件恢复入口，需使用事先保留的副本。这里不做跨文件事务或自动修复。
