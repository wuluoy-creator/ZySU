# SUMH 模块路径规则

模块规则草稿与 Maps 草稿已移到应用私有存储，支持读写错误重试、容量反馈和外部配置刷新时的明确选择；累计预算为 512 项 / 4 MiB。已保存配置仍遵守下述规则及 IPC 上限。草稿不是生效配置，内核运行状态可用[运行状态查询](sumh-runtime-state.md)核对；新查询不能代替普通应用验证。

模块挂载设置现在可以直接编辑 SUMH 已有的路径隐藏能力。路径规则与模块的挂载模式一并保存，沿用原有模块规则文件和内核映射流程。

仅使用模块少数文件、排除目录保留子项、目录合并及本次启动热暂停等完整操作见[场景化使用指南](sumh-usage-scenarios.md)。第九批已接入 CLI 计划预览、路径解释和 Manager 五类草稿模板；第十批增加单模块 inspect、normalize dry-run 和额外分区管理。它们尚未完成设备验收，明确重新应用仍未实现。完整范围见[全面改进计划](../../plans/SUMH-comprehensive-improvement-plan-2026-10-16.md)。

## 模式与生效范围

路径规则仅在模块实际使用 SUMH 时生效。模块整体仍可选择 Auto、SUMH、OverlayFS、Magic Mount 或不挂载；非 Auto 的全局挂载设置会覆盖模块选择。Auto 当前按条件选择 OverlayFS 或 Magic Mount，因此需要显式选择 SUMH 才会使用这些路径规则。

| 路径模式 | 行为 |
| --- | --- |
| Auto / SUMH | 使用已有 SUMH 虚拟映射 |
| 不挂载（`none`） | 跳过该模块在此路径的映射，保留系统原路径 |
| 隐藏（`hide`） | 使用已有路径隐藏机制隐藏目标；它也可以指定模块树之外的绝对路径 |

普通映射按最长路径前缀匹配，`none` 目录下可通过更具体的 SUMH 规则恢复模块映射。隐藏父目录会使其子路径不可访问，不能用子路径映射重新打开被隐藏的父目录。不同模块共享最终文件视图，模块规则不代表独立的应用权限范围。

旧版路径规则中的 Overlay/Magic 仍能读取和保存，但在 SUMH 编译器中按 SUMH 映射处理，不会为子目录创建另一种挂载。管理器只在编辑旧规则时保留这些选项并说明行为；新规则提供实际可用的 Auto、SUMH、不挂载和隐藏。

管理器保存后提示重启生效，不会自行切换当前挂载后端。内核不支持 SUMH 时可保留或移除已有定义，新增或修改 SUMH/隐藏规则需要受支持的内核。

`config apply` 不会例行重新编译已经激活的模块映射，因此不能把它当作修改模块路径规则后的通用热刷新命令。已有 `module hot-unmount` / `module hot-mount` 只处理本次启动已归属 SUMH 的模块，并可能重建整个集合；明确的“预览后重新应用”入口仍在计划中。

## 源对象身份与更新边界

第二十七批起，普通映射在捕获源路径后，源 inode 标记及目录视图安装复用同一批捕获引用，不再按目标字符串查找另一个对象。第二十八批进一步让非链接源只做一次原生不跟随末尾链接的查找，元数据和安装直接使用该对象。显式重新登记普通映射时，即使目标文字相同，源挂载或 inode 已变化也会重新安装相应父目录副作用。

符号链接保留原生 nofollow/FOLLOW 查找，以保留绝对链接、`..`、进程根、挂载、magic link 和权限策略。第三十一批在 FOLLOW 成功后按原路径再做一次 nofollow，完整 mount+dentry 与初始叶对象不相同返回 ESTALE；查找失败返回原始错误，SUMH 不自动重试。MERGE 子链接另保留首次查找与借用叶对象的比较。后置检查只拒绝仍能观察到的变化：A→B→A、动态链接、祖先或目标链变化及检查后的替换仍未解决，不是原子或防 ABA 的成对捕获。目录末尾斜杠沿用原生查找语义；初始查找已取得目录时继续单次对象捕获。

MERGE 规则持有完整的挂载与目录引用；每次目录收集和根目录物化直接打开持有的对象。源路径被 rename、替换或挂载位置改变后，原规则不会仅因字符串现在指向另一目录就自动切换根对象；实际打开仍可能返回文件系统或权限错误。同一目录对象内的内容继续可变，每次读取重新收集名称，既有游标也不是固定目录快照。重复嵌套规则复用原根；顶层重复 MERGE 仍返回已存在，不能用重复登记当刷新接口。

注册前基于捕获目录检查 `.replace`，存在时拒绝；缺少兼容目录查找接口返回 EOPNOTSUPP，目录锁竞争返回 EAGAIN，其他查找错误原样返回。物化每个目录时，先收集名称至 EOF，关闭迭代文件并退出目录迭代锁，再按持有父目录解析单个不跟随末尾链接的名称；类型取自实际 inode，兼容 DT_UNKNOWN 或过期的目录项类型。非链接映射和嵌套目录直接使用捕获对象，描述路径不会重新选择源根。可见目录查询的权限/I/O 错误会停止物化，仅 ENOENT/ENOTDIR 按缺失处理。

一次递归物化共用上限：1024 个目录、16384 个非点名称、65536 条原始记录、65536 次迭代调用、4 MiB 名称队列与拼接路径工作区，根深度为 0、最深为 8。此内存预算不包含已发布规则或 VFS 内部分配。超限返回 E2BIG，循环/超深返回 ELOOP，非法名称或有记录但 cookie 不前进返回 EIO；不会截断路径或把半目录当作完整结果。父规则和此前子项仍可能已经发布，因此失败不等于零修改。引用不会冻结内容；同一目录内替换子项、原地写入、旧 FD 和新 open 仍需分别验证。

需要采用替换后的源树时，保存正确配置并按现有受支持阶段重新规划，通常重启生效。`config apply` 不是通用热重编译；部分发布或未知结果先查询[模块重建记录](sumh-module-rebuild.md)，不循环重试 EAGAIN/ESTALE 或用全局 clear 撤销单条规则。源引用修正没有引入模块 owner 原子提交；第三十三、三十四批已让必要的注入和目录挂接准备失败明确返回，旧的可选源 spoof 标记仍是独立环节。宿主结果与未执行设备门禁见[第二十七批验证](../../plans/SUMH-implementation-validation-batch27-2026-10-17.md)、[第二十八批验证](../../plans/SUMH-implementation-validation-batch28-2026-10-17.md)和[第三十一批验证](../../plans/SUMH-implementation-validation-batch31-2026-10-17.md)。

## 注入目录归属与撤销边界

第三十三批代码将注入目录索引绑定到实际的映射或 MERGE 记录；集成验证进度见[本批记录](../../plans/SUMH-implementation-validation-batch33-2026-10-17.md)。多个规则共用同一路径键或同一个 inode 时，删除其中一个不会清除其他规则仍在使用的注入状态。普通映射重新登记时，即使目标未变，也先取得新声明，再撤销旧声明。延迟回收按原对象释放引用，不根据已经可能改变的路径清除标记。

这里的 `inject` 列表项是派生索引，不是可独立编辑的用户规则。底层 DEL 请求命中精确映射时撤销该映射自己的声明；没有精确映射或原有隐藏规则、仅剩派生键时返回 EBUSY，并保留目录挂接及隐藏位。不要把 EBUSY 当成需要全局清空的信号；应确认生成它的模块配置、[重建结果](sumh-module-rebuild.md)和运行集合，再按既有支持的生效阶段处理。尚无按模块 owner 精确撤销入口。

新的注入准备只将 ENOENT 视为缺失：普通 ADD 的父目录确实不存在时可不绑定，物化前缀和 MERGE 可保存未绑定路径键。其他查找、非目录、分配、路径渲染或 FOP 安装错误会返回，不能解释成正常缺失或自动降级。必要的注入和目录挂接准备错误会阻止该条发布；可选源 spoof 标记仍独立处理。MERGE 父规则和早先子项也可能已经发布，所以错误不保证整个操作没有修改。

这些引用不固定源树，也不提供全局回滚。恢复保存配置仍须审查当前源文件并按支持阶段应用；不得将全局 clear 作为单条规则、单模块或测试规则的通用撤销方式。真实卸载、旧 FD、并发和普通应用观察仍需设备验收。

## 目录缓存与原子打开的当前边界

第四十批已在源码中补强普通父目录的查找/打开路径：准备时等待已经开始的原生查找结束；PREPARED 仍显示原生视图，但返回结果会纳入观察者重验证。选中映射的 atomic_open 使用相同的 SUMH 解析结果，不因为底层支持原子打开而创建原生目标；内存不足或解析过期明确失败。

规则替换后，旧源投影不再仅因同为 SUMH vnode 就被当成新结果。已有 FD 仍指向其捕获源；这不会刷新源文件内容、重新编译模块或提供按模块原子恢复。遇到 EAGAIN/ENOMEM 或部分完成时保留原配置并查询状态，确认原因后再按现有生效阶段操作，不循环全局清空。

这些保证只覆盖已实现的普通回调路径。FUSE READDIRPLUS、纯虚拟后代和文件系统内部短暂缓存窗口仍有未闭合项，不能据此声称所有文件系统或所有观察者立即一致。设计和实际验证分别见[目录缓存设计](../../plans/SUMH-dirhijack-cache-design-2026-10-19.md)与[第四十批记录](../../plans/SUMH-implementation-validation-batch40-2026-10-19.md)。明确模块重新应用、受管重定向和元数据扩展尚未开放。

## 编辑与校验

编辑器提供逐项编辑、移除、放弃当前单项编辑、内联错误和保存失败反馈；旋转屏幕后保留当前编辑内容。关闭整个对话框仍保留模块草稿，目前没有始终可用的整份草稿重置按钮。路径中的空格和 Unicode 原样保存，不再自动裁剪末尾空格。

模块路径用于文本前缀匹配，因此要求规范的绝对路径：允许 `/`，其他路径不能包含重复斜杠、`.` / `..` 路径段或末尾斜杠。NUL、回车、换行以及 UTF-8 长度达到 4096 字节的路径会被拒绝。这里的约束不同于独立的受管隐藏路径；两种入口的用途和原有解析机制不同。

每个模块最多 256 条规则，同一完整路径只能出现一次。规则数组经过两层 JSON 编码后的预算为 56 KiB，管理器和控制器执行相同校验，避免长路径在传输时失败。达到条数上限仍可编辑已有规则。

已有配置中旧版允许的末尾斜杠、重复路径或超额列表仍原样读取，不会因新输入约束而停止全部模块。管理器显示问题并允许编辑或移除，提交完整列表前需满足新约束；CLI 的模式修改保留旧规则，移除命令可逐项减少旧列表。不会自动规范化旧路径或改变其前缀匹配含义。

## 原子保存与 CLI

### 五类规则模板

在模块挂载设置中打开“规则模板”，选择全部使用、排除路径、仅使用选定路径、排除目录但保留子项或隐藏指定目标。路径逐行输入，保留 Unicode、制表符和末尾空格；换行是分隔符，不能加入空行。父目录排除使用 `none`，必须选择严格位于父目录下的子项；父 `hide` 不能用此方法开放子项。

先完成或放弃正在编辑的单条规则，再生成模板。点击审查后，界面展示相对**当前编辑草稿**的模式、增改删和完整候选列表；“替换草稿”把模式设为 SUMH 并替换全部草稿规则，仍需使用原有保存按钮。全局后端覆盖提示、外部保存冲突以及草稿变化会要求重新审查。取消或关闭对话框保留模板输入和主编辑草稿，失败不自动保存或应用。替换前记录原完整模式/规则；保存前如需撤销，在编辑器中手动恢复记录的完整定义，不能把关闭对话框当作恢复。已经保存的变更应恢复原完整模式/规则并重启。

模板与手写规则等价，“全部使用”的候选列表为空，表示去除该模块所有路径例外。原始模板输入最多 64 KiB，生成列表仍为 256 条 / 双层 JSON 56 KiB；模板不执行设备预检，也不会调用下面的 CLI Planner。

### 只读计划预览与路径解释

以下精确入口为第九批已实现的本地 CLI，要求授权 root 和已经存在的控制器私有目录：

```sh
/data/adb/ksud sumhp module plan
/data/adb/ksud sumhp module explain /vendor/etc/example.conf
/data/adb/ksud sumhp module plan --input /data/local/tmp/module-plan.json
/data/adb/ksud sumhp module explain /vendor/etc/example.conf --input - < /data/local/tmp/module-plan.json
```

入口在日志初始化、普通参数解析和 daemon 恢复之前分派。它不创建运行目录或配置锁、不保存、不恢复、不规范化也不安装规则。错误参数原地拒绝；不要加全局选项包装或通过 daemon 嵌套调用。`--input -` 从 stdin 读一个完整 JSON；绝对文件路径只接受不跟随符号链接的单链接普通文件。候选内容只修改内存副本，例如：

```json
{
  "schema_version": 1,
  "kind": "sumh.module.plan.input",
  "config": {"mount_backend": "sumh"},
  "modules": [{
    "id": "example.module",
    "mode": "sumh",
    "rules": [
      {"path": "/", "mode": "none"},
      {"path": "/vendor/etc/example.conf", "mode": "sumh"}
    ]
  }]
}
```

`config` 和 `modules` 均可省略。config 仅允许 `mount_backend`、`overlayfs_enabled`、`magic_mount_enabled` 和 `partitions`；每个模块必须提供完整 id/mode/rules，以替换该模块的候选定义。输入总计 64 KiB、最多 256 个模块替换；每个规则列表沿用 256 条 / 56 KiB 限制。重复 JSON 键、重复模块 ID、未来版本、未知字段和无效 UTF-8 都会拒绝，原配置保持不变。该示例中的全局 SUMH 选择也只是候选比较，未保存。

结果为 schema 1 / `sumh.module.plan`。重点阅读：

| 字段 | 含义 |
| --- | --- |
| `status` / `comparison_valid` | complete 仅表示此范围内 SUMH 编译完整；partial、unknown、invalid 或 stale 不可当作空计划或应用成功。stale 会使差异失效。 |
| `configuration` / `baseline` / `candidate` / `diff` | 保存/候选配置、后端决定、实际 Planner 的有序 ADD/MERGE/HIDE 贡献及差异；配置缺少可挂载模块时单独列出。 |
| `trace` / `explain` | 全局与模块后端来源、实际匹配规则、别名、模块发出顺序、被后续直接映射覆盖的贡献、隐藏祖先及 MERGE 回退原因；筛选后的事件为空不证明路径不存在。 |
| `source` / `write_policy` | 现有映射的源位置和写透语义；不是新的只读用户重定向接口。 |
| revisions / `runtime_context` / `ownership` | 原始配置、候选与源元数据摘要、运行 token 及本次启动标记；不能作为应用授权。外部 owner 为 `not_observed` / null，未检查是否冲突。 |
| `unchecked` / `requires_reboot` / `apply_token` | 明列未检查项，保守要求重启，应用 token 为空；尚无配套 `module apply`。 |

文件系统路径和来源采用与 inventory 相同的字节对象（有效 UTF-8 文本或 hex），不要把整个对象直接当作路径字符串。编译只覆盖**当前可挂载模块**，沿用 disable/remove/skip_mount/本次启动热暂停过滤；不等于完整的下次启动计划。它保留生产模块优先级，不能确定 MERGE/其他后端最终赢家，也没有读取普通应用视图或核对完整运行映射集合。

采样在有 5 秒等待预算的 init 挂载命名空间子进程进行；前后核对配置、模块发现、boot/运行 token，并两次编译比较元数据。外部 owner 本批不采样，不调用无读取预算的旧发现接口；没有固定源对象、内容哈希或消除 ABA 的承诺。模块目录扫描上限 512 项（包括跳过项），诊断 2048 事件 / 4096 元数据记录 / 512 KiB，总动作 4096，独立响应 2 MiB；达到预算停止预览，不扩大普通 IPC。超时、目录锁忙、缺私有目录或权限错误报告未知；先排查原因再手动重读，预览失败不会触发修复或重试变更。

撤销预览只需丢弃候选文件或草稿，运行规则不受影响。保存应使用既有 `module configure`，保存后的重启要求不变。不要把 revision 当作事务 token，也不要将当前 root 观察替代应用验证。

### Manager 计划预览与路径解释

第十七批新增当前可用的 Manager 入口：模块设置→“计划预览与路径解释”。先完成或取消正在编辑的单条规则，再打开预览。打开窗口本身不读取 Planner；分别点击“读取已保存配置”或“比较当前完整草稿”。草稿比较替换当前模块的完整模式和有序规则列表，空列表表示候选中清除该模块例外；其他模块和全局设置沿用保存值，不会为了让模块使用 SUMH 而改变全局后端。

路径输入可留空以查看整个计划，也可输入原始绝对路径后手动读取。保留 Unicode、制表符及末尾空格，不 trim 或执行 shell；拒绝非规范路径、NUL/换行、无效 UTF-8 和超过 4095 字节的路径。界面引用路径文本，非 UTF-8 文件系统路径以 hex 展示。候选输入上限 64 KiB；既有 256 条和 56 KiB 编码约束继续适用，旧保存记录的展示不套用新写入限制。

保存、候选及差异视图共用上节的生产响应。后端决策、模块发出顺序、ADD/MERGE/HIDE 贡献、源文件写透落点、隐藏祖先、别名和前一直接来源均来自生产 Planner。差异只表示有序 SUMH 编译贡献的变化；完整编译不保证最终运行赢家、外部 owner 无冲突或普通应用观察。无相关路径事件不证明目标不存在。缺少当前可挂载候选模块、部分结果、输入变化和传输失败分别报告，不以空列表冒充成功。

结果绑定实际提交的候选摘要、完整目标定义和解释路径。修改草稿、解释路径、观察到的保存基线或后端上下文后，旧结果过期；改回原值也不会重新有效，须手动再读。关闭窗口丢弃观察，已开始的有界读取结束前不启动第二个读取。Activity 内只保留一个观察；完整结果和候选不写入 Bundle。进程重建不恢复旧结果或自动请求，解释路径只是小型页面状态，模块草稿仍沿用私有存储。

独立能力协商失败或缺失时显示错误/不支持，不回退到可能启动 daemon 的普通命令。私有预览通道不保存、迁移、normalize、恢复规则或应用挂载。预览仍限 2 MiB，4096 字节帧和既有总期限保持不变；普通 IPC 容量不扩大。关闭无需撤销运行状态；实际保存仍用原模块设置，重启要求不变，预览不是保存授权或 `module apply` token。实现与主机/设备证据分开见[第十七批验证](../../plans/SUMH-implementation-validation-batch17-2026-10-16.md)。

### 保存入口

```sh
# 一次保存模块模式与完整路径规则列表；空数组会清除这个模块的路径规则
ksud sumhp module configure example.module sumh \
  '[{"path":"/system/app/Example","mode":"hide"}]'

# 查看保存的配置和实际后端信息
ksud sumhp module list --all

# 原有单项操作仍可使用，内部共用同一保存流程
ksud sumhp module set-mode example.module sumh
ksud sumhp module add-rule example.module /system/app/Example hide
ksud sumhp module remove-rule example.module /system/app/Example
```

管理器通过一次 `module configure` 请求提交完整设置。控制器在文件锁内读取、校验、修改并原子替换 `module_rules.json`，模式和规则一起成功或一起保留原值；不再先改模式，再逐条删旧规则、加新规则。其他模块的配置一并保留。旧控制器未声明 `api meta` 的 `module_configure` 能力时，管理器会提示更新并重启控制器。

`module configure` 的规则数组会替换该模块的完整路径规则，示例不是增量追加。编辑前记录原有模式和全部规则；已有其他定义时先合并再提交。恢复也应提交原完整定义，不能用空数组代替撤销最近一次编辑。

旧版 `module_mode.json` 和数组形式的 `module_rules.json` 仍能读取。首次成功修改时，将两者合并写回原有的 `module_rules.json`，每个模块使用 `{ "mode": "…", "rules": […] }`。显式保存 `auto` 和空规则，避免旧文件中的模式重新生效。旧模式文件保留作为升级输入，新的对象条目优先。迁移后需要配套新版控制器；旧版不能识别新对象格式，直接降级可能忽略规则并重新使用旧模式文件。

损坏、不可读或不合法的保存配置会报告错误，不能当作空列表覆盖。模块重放先读取并验证配置，失败时不清空已有模块映射；需修复配置后重试。原子保存只负责持久化，当前挂载的重建仍沿用已有生命周期。

## 挂载与路径规划

SUMH 在 init 挂载命名空间中解析模块规则和目标路径。例如设备的 `/system/vendor` 指向 `/vendor` 时，以两种路径填写的规则会按同一个目标匹配，嵌套的 `none` 或 SUMH 例外也会阻止父目录被整体合并。解析到同一目标的等价定义合并；不同模式的别名定义报告冲突，不再依赖隐含覆盖顺序。保存文件里的原始路径保持不变。

包含 whiteout 的目录按条目编译：普通文件继续使用已有虚拟映射，字符设备 `0:0` 和带 `trusted.overlay.whiteout` 属性的空文件使用已有隐藏规则。该目录不会直接进入无法表达这些条目的整目录合并。`.replace` / opaque 等原生 SUMH 尚不支持的目录替换仍会拒绝。

热重放先完成新模块树和规则的编译，再清理旧映射，并应用同一次编译得到的计划。别名冲突、扫描或元数据错误、不支持的目录替换在清理前失败，旧映射保留。内核 ioctl 拒绝或编译后源文件变化仍可能使安装失败；这类错误发生在清理之后，沿用现有部分安装清理流程，不能视为内核规则的原子替换。

各挂载后端和模块列表共用内置分区加额外 `partitions` 的集合，按名称去重。增加自定义分区不会让 SUMH 或 OverlayFS 忽略 `system`、`vendor` 等内置分区。

显式选择 OverlayFS 也会检查模块布局。分区根直属文件或普通符号链接无法作为 OverlayFS 叶目录，按已有回退规则选择 Magic Mount，或在其被禁用时选择 none，并记录原因。安装器生成的本地分区别名单独识别，不能把任意目录符号链接当成相同能力。

热挂载/卸载命令在重建前检查未解决的记录，再检查并写入本次启动的模块状态标记。标记写入、删除或读取失败会阻止重建；只有确认内核尚未修改的失败才尝试恢复旧选择。映射部分完成、结果未知或已完成后功能恢复失败时保留本次选择，不声称运行状态已回滚。第二十四批新增精确本地 `module rebuild-status`，保留计划与调用回执，阻止同启动未解决结果再次重建；详见[模块重建记录与失败处理](sumh-module-rebuild.md)。已有挂载配置损坏或不可读时，挂载命令停止执行；只有配置文件不存在的首次安装场景才使用默认值。

### 长路径和目录读取失败

第二十批将活动目录包装器的路径缓冲从 512 字节改为按需分配的 `PATH_MAX` 堆缓冲，内容最多 4095 字节，另加结尾 NUL。该范围按字节计数，保留 Unicode 和内核文件名原始字节；不扩大内核栈。只有需要注入条目的目录申请该缓冲，单纯隐藏过滤只申请小包装器。

准备时内存不足返回 ENOMEM，解析路径过长返回 ENAMETOOLONG，其他解析错误原样上报。失败不会继续调用原始目录枚举，也不改变本次调用进入时的目录游标。不要把错误当作空目录或成功读取；先保留失败路径、所选后端及运行状态，再检查路径长度、挂载来源和资源情况，原因消除后重新读取。目录读取没有修改规则，无需清空或重新应用全局集合。

旧指针 ioctl 的 `PAGE_SIZE` 接收范围保持兼容；16 KiB 页内核能接收某个长字符串，并不证明该路径可被整个映射链路解析。4095 字节也不是单个文件名的上限，文件系统单组件限制仍适用。模块规则和 Maps 的既有格式及传输预算保持不变。

第二十一批将通用 MERGE 的注入与去重改为共用完整的本次调用收集结果，移除了前四个目标的 dentry 缓存限制。第二十七批进一步在规则登记时固定源根，每次读取直接打开规则持有的目录引用并重新收集名称；规则或内容变化仍不保证跨调用固定视图。长路径准备证据见[第二十批验证](../../plans/SUMH-implementation-validation-batch20-2026-10-16.md)，收集器预算见[第二十一批验证](../../plans/SUMH-implementation-validation-batch21-2026-10-16.md)，当前根引用语义见[第二十七批验证](../../plans/SUMH-implementation-validation-batch27-2026-10-17.md)。

单次收集最多处理 1024 个目标、16384 个发出/抑制名称节点合计、65536 个原始记录和 65536 次目标迭代调用，请求分配峰值限制为 4 MiB。名称节点可能同时用于发出和抑制，不能把 16384 理解为可见文件数。超限返回 E2BIG，内存不足返回 ENOMEM；目标解析、打开或迭代失败也会明确返回。收集失败时不会输出前半份目录或推进源目录游标。该预算不包含文件系统内部分配、分配器开销或多个读取者的全局内存。

动态 `.replace` 标记只抑制原目录中的同名项，不输出自身，不因此获得 opaque 替换语义。普通字符项的 whiteout 检查需要查找能力：缺失返回 EOPNOTSUPP，目录锁暂时忙返回 EAGAIN，身份或类型改变返回 ESTALE。SUMH vnode 目标和已投影字符项当前也明确返回 EOPNOTSUPP，需后续底层支持。遇到这些错误先保留路径、后端、错误码和日志，确认相应原因后重新读取；读取本身不需要全局 clear 来撤销。真实文件系统锁、并发和性能验收仍未完成。

第二十二批为 6.16+ 的新查找签名增加类型明确的适配；只在精确函数和身份映射对象均存在时启用，缺依赖仍返回不支持。参见[目录查找兼容指南](sumh-kmi-compatibility.md)。这不解除 vnode 目标或已投影字符项的独立限制，也不把版本字符串作为 KMI 支持证明。

## 隐藏路径与内核规则

规则页的“隐藏路径”管理用户保存的隐藏定义，包含等待绑定、失败、暂停及尚未应用的条目。“内核规则”显示实际返回的路径规则、已绑定受管隐藏及开启的功能；同一路径隐藏记录不重复计数，待绑定定义不会计入内核记录。

内核 `management=SUSPENDED` 表示 SUMH 全局停用，是输出字段，不能写入以暂停单条规则。第十三至十六批已实现基于稳定定义 ID 的逐条/按组启停及 Manager 工作流，见[用户隐藏定义与启停](sumh-user-hide-definitions.md)；停用保留定义并撤销对应用户受管登记。用户受管隐藏与模块 HIDE 分开管理，移除前者不会保证同路径不再被后者隐藏。

内核文本规则列表可能被截断，且旧格式没有转义路径对。界面会提示读取不完整；无法确定分界的路径对按原文显示。记录数量只统计当前可显示项，路径视图的实际生效仍受 SUMH 总开关和应用策略控制。

## 模块开发预检与规范化预览

当前可用，仍需真实设备验收。先在有真实普通 `module.prop` 的独立开发目录检查；路径必须为规范绝对路径，不可包含符号链接祖先。以下不会保存、恢复、挂载或修改模块：

```sh
/data/adb/ksud sumhp module inspect /data/local/tmp/example.module
/data/adb/ksud sumhp module normalize /data/local/tmp/example.module --dry-run
```

`inspect` 调用生产后端选择与 SUMH Planner，保留保存的全局后端、开关和额外分区。精确安装目录下使用对应保存的模块规则；其他开发目录使用独立候选身份、请求 SUMH，不借用同名模块的规则。它只编译该模块，不按停用标记过滤；不能解释多模块最终赢家、外部 owner、实际挂载或应用可见性。生产编译器遇到的别名、whiteout/opaque、符号链接和后端限制会进入结果；首个失败可能中止后续检查。全局选择其他后端或 SUMH 不可用时，不能据此声称完成了其预检。

`normalize --dry-run` 列出创建目录、移动目录、创建链接、无需修改和跳过项。实际 `module normalize <目录>` 是独立变更，重新规划和复验，禁止覆盖现有目标；使用同一算法，不会将先前输出直接当成授权 token。固定处理 vendor/system_ext/product/odm/oem，不处理任意额外分区。需要 `renameat2(RENAME_NOREPLACE)`；不支持时明确失败。

执行前保留开发目录备份。执行结果里的失败项仍可能 `effect_observed:true`，需结合 `durability_confirmed`、已完成项与恢复提示检查现场；不要用全局 clear 或递归删除“回滚”。目前逐项结果只在回包中，没有持久逐项恢复日志。断连、退出或部分完成后先重新 dry-run/inspect，核对剩余布局再明确继续。元数据一致不等于内容被固定，也不是跨步骤事务。

## 额外分区：发现、选择、仅保存

Manager 的设置→挂载→额外分区支持手动发现。先查看保存名字与候选来源，勾选增删项，预览完整差异，再“仅保存选择”；重启后使用。已保存但暂时无法识别的名字会保留，只有明确移除才删除。退出对话框保留草稿；重新打开/进程恢复后需要重新发现。外部配置变化时明确保留自己的增删意图并再次审查，失败不清空选择。

精确本地 CLI 等价入口：

```sh
/data/adb/ksud sumhp config discover-partitions
# 用本次响应的 config_revision 替换占位值；数组是完整列表，保留原有名字。
/data/adb/ksud sumhp config set-partitions 'sha256-v1:<本次发现的64位摘要>' '["existing_part","example_extra"]'
```

示例摘要与名字是占位内容，不能原样执行。revision 变化返回 conflict；新增名字在保存时重新检查资格。最多 128 个不重复的 ASCII 字母/数字/下划线/连字符名字，每个最多 255 字节，数组最多 40 KiB。发现缺失、不完整、过期或配置未知时禁用选择保存；不要将它当成空集合。没有候选不意味着可以删除已有定义。发现覆盖禁用模块并展示状态，但候选资格不等于后端挂载就绪，也不证明普通应用可见。

查询最多返回 512 KiB，检查已安装模块、真实分区和平台别名，不跟随未知的模块外部链接。具有不确定挂载来源的目标不能用于新增。`config sync-partitions` 现在也是只读发现的兼容入口，不再声称 Added，也不自动保存。

保存返回 saved、unchanged、conflict、rejected、failed、partial 或 unknown；真正 saved 必须完成耐久写入并读回，unchanged 只表示无需重写的当前值匹配。partial/unknown 先重新发现，再决定是否明确保存，程序不自动重复。该独立保存入口不调用 `config apply`，不启动恢复 daemon。撤销时重新发现当前 revision，恢复事先记录的完整分区列表并单独保存、重启；恢复配置不等于还原当前挂载。
