# SUMH proc 视图内存预算

本指南对应 K01 的第一阶段及第二十五批 K05 扩展：已成功安装代理的 proc 视图与 Maps 规则集合，使用统一的 **16 MiB 请求分配字节预算**。快照、流缓冲、临时工作区和所有存活代的 Maps 规则共同计费，避免多个打开文件各自满足单份限制、合计却持续增长。

这里的字节数是 SUMH 向分配器请求的对象/缓冲容量，不是整台设备的实际内存占用。分配器取整和元数据、原生 VFS/seq 对象以及逐文件 proxy 对象不在本阶段预算内。代理安装失败的可靠拒绝入口仍待完善，K01 尚未全部完成。

## 计费范围

| 类别 | 包含内容 | 释放时机 |
| --- | --- | --- |
| snapshot | 快照对象、mountinfo 与 mounts 两份缓冲 | 最后一个快照引用释放；构建失败回滚；明确重绕成功后按已有流程丢弃旧快照 |
| stream | Maps 和分组归一化视图的原始/过滤缓冲 | 最终关闭；终止性读取、解析、扩容错误清理；其他已有显式释放路径 |
| workspace | 原生挂载过滤条目、传播组引用和 ID 数组、受管 Maps ioctl 输入副本 | 对应操作结束，包括失败分支 |
| maps | 当前、准备发布、被旧读取流持有的不可变规则集合 | 最后一个集合引用释放；准备失败/未发布回滚。清理当前规则不会提前回收旧流仍持有的集合 |

扩容时先预留整个新缓冲，旧缓冲释放后才退还旧容量。因此短暂同时存在的新旧内存也占预算。输出过滤后变短不会提前退还仍然分配的容量。开关切换、generation 变化或暂时不使用某功能，不会把仍被打开文件持有的内存计数清零。

每份 mountinfo/mounts 缓冲仍从 64 KiB 开始，最多 1 MiB；Maps 流自身原有上限保持不变。统一预算会让此前未计费的多个读者相互竞争，能够同时保留的文件数量取决于实际分配容量，不能固定换算成可打开文件数。

## 观察预算与错误

**目的：** 在测试设备中核对多读者压力、扩容失败和关闭后的回收。

**适用条件：** 使用包含该实现的内核，控制器与内核可通信。先确认是自有测试进程和合成数据；root 查询统计不代替普通应用的读取验证。

**入口：** 既有 `api hooks` 的内核诊断文本新增一行：

```text
proc requested memory: scope=snapshot+stream+workspace+maps proxy=excluded used=... limit=16777216 peak=... snapshot=... stream=... workspace=... maps=... denied=... allocation_failed=...
```

这不是 `api capabilities` 中的新结构化段。`api hooks` 仍使用既有查询路径，不能套用能力中心“不启动 daemon/自动恢复”的独立只读承诺。旧内核没有该行时，表示没有这项统计证据，不能解释为零占用。

**步骤：** 记录初始 used；让自有普通应用分别保持 mountinfo、mounts、maps/smaps 的 FD 并触发读取；再次记录 used/peak 与分类值；按应用顺序关闭 FD，最后记录回收值。复制 FD 共享文件对象时，要等最终引用关闭才期待回收。保持其他读者不变，按本次测试前的基线比较，不能要求整机 used 必然为零。

**期望观察：** 已计费范围的 used 不超过 limit，分类值之和等于同一次统计的 used。peak 是本次模块生命周期内的历史峰值；denied 记录预算拒绝，allocation_failed 记录预留成功后真正的分配器失败。计数来自短锁保护下的一次观察，返回后运行状态仍可变化。

**失败处理：** 预算耗尽和分配器失败沿原读取路径报告 `ENOMEM`，计数帮助区分原因。已有代理的快照读取失败不会输出半份或原生未过滤数据。Maps 终止性失败释放缓冲，保留首次错误，后续非零读取仍按既有行为返回 `EIO`；调用者可关闭后明确重新打开。用户缓冲复制的 `EFAULT` 保留可重试数据，不按终止性解析失败处理。分组视图错误被缓存，成功的明确重绕可按原流程允许重试；不会后台循环重试。

**撤销：** 关闭本次测试拥有的 FD、退出测试进程并恢复测试配置即可；不用全局 clear 回收缓冲，不复位统计来掩盖仍存活的分配。本预算没有新增用户可调开关或在线放大入口。

Maps 每条流在第一次非零读取固定规则；规则反复替换时，旧 FD 可以保留多个旧代，因此其占用不能只按当前规则数计算。`maps` 分类包含这些旧代和准备发布的新代。规则写入也可能因读者占用预算而返回 `ENOMEM`，确认未发布时旧集合保持完整。关闭自有旧 FD 后可以明确重试；Maps 流缓冲和规则共同竞争此预算，尚未提供按来源的内存保留额度。规则数量上限与读取更新语义见 [Maps 指南](sumh-maps-rules.md#规则快照与读取中的更新)。

## 尚未覆盖的入口与证据

现有 `fd_install` 探针不能把代理安装错误直接返回给 open 调用者，安装失败仍可能保留原生 fops。本阶段没有在该入口增加新的 proxy 配额拒绝，避免把预算压力引入这条回退路径。完整 K01 需要另行实现可靠拒绝、原始 release/fops 引用及模块生命周期闭环，再对 proxy 对象计费。

生产函数提取的宿主测试可检查计费顺序、故障回滚和错误分支；真实并发、分配器物理成本、kprobe/CFI、四 KMI 构建、普通/isolated 观察者及 lockdep/KASAN/设备压力仍需要独立验证。详见[第十九批记录](../../plans/SUMH-implementation-validation-batch19-2026-10-16.md)及[54 项账本](../../plans/SUMH-implementation-progress-2026-10-16.md)。
