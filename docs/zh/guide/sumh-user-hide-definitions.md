# 用户隐藏定义、分组、启停与交换

第十三批实现稳定定义和条件 CLI，第十四批把名称、备注、分组、停用项和逐条/按组启停接入 Manager。新界面复用已有列表、多选和私有草稿；原路径导入工具保留为明确切换的兼容入口。源码及宿主验证记录见[第十三批](../../plans/SUMH-implementation-validation-batch13-2026-10-16.md)和[第十四批](../../plans/SUMH-implementation-validation-batch14-2026-10-16.md)，完整范围见[全面计划](../../plans/SUMH-comprehensive-improvement-plan-2026-10-16.md)。第十五批接入提交前 ID 和持久结果恢复，见[第十五批验证](../../plans/SUMH-implementation-validation-batch15-2026-10-16.md)；第十六批增加完整/选中定义文件交换、冲突预检和分组提交，见[第十六批验证](../../plans/SUMH-implementation-validation-batch16-2026-10-16.md)。真实设备验收仍待完成。

## 定义和运行条目

每条定义保存六个字段：`id`、`path`、`enabled`、`name`、`note`、`group`。稳定 ID 为 32 位小写十六进制字符串，与内核临时 rule ID/generation 分开。名称、备注和分组不改变路径匹配；分组按原始字符串精确匹配，空字符串表示未分组。停用保留定义，只撤销对应用户受管注册；再次启用重新注册。同路径的模块 HIDE 不属于此入口的删除范围。

`SUSPENDED` 仍表示全局 SUMH 停用，不能作为逐条启停参数。定义 enabled、运行注册、路径绑定以及普通应用的实际视图是不同状态。注册成功且 pending 可能只是在等待父目录出现；绑定错误也不等于定义保存失败。root 查询不能证明普通应用的可见性。

新建、启停、按 ID 删除及重试要求受管用户隐藏能力；不支持或能力读取失败时拒绝提交，不使用全局 clear 代替。`annotate` 仅改元数据，不要求内核可用。旧路径 add/remove 保留旧内核兼容行为；不应将该兼容分支当作拥有模块/用户所有权隔离的证明。

## Manager 定义工作流

**目的与条件：** 在配套第十五批 Manager/控制器中管理自己的隐藏定义，保持稳定 ID 和原始路径。启停、新建、删除和重试要求受管所有权；仅修改名称、备注和分组允许内核不可用。首次进入或返回前台读取状态，查询不完整时保留已知条目并关闭修改入口，不能把残留列表当作完整结果。

**入口与步骤：** SUMH → 规则 → 用户隐藏默认打开“全部定义”，同时显示启用和停用项。可搜索路径、名称、备注、分组，筛选启用/停用/需处理，或选取精确组名。点击条目编辑元数据；新增可选择“保存后启用”，关闭时保存为停用。单项菜单启停；多选支持启停、重试和删除。重试只对仍启用的定义开放，等待绑定不需要持续重试。

选择组后“启用整组/停用整组”会列出整个精确组的成员，包含搜索或筛选隐藏的项。确认绑定当时的完整文件 revision 和 boot ID；刷新后版本变化必须关闭确认框并重新审查，不能静默扩大范围。多选按稳定 ID 逐项提交，每次仅从确认回包推进 revision；第一项失败、部分完成或未知即停止，显示已尝试与未尝试数量。“停止”只阻止后续项，不能取消已经送达的命令。整组命令一次保存目标定义再逐项同步，仍可能部分完成。

**期望观察：** 每行先展示定义启用状态，再展示用户注册与绑定状态。停用条目仍在列表；已停用但运行残留单独提示。元数据保存和注册匹配使用不同结果文案，bound/pending/binding_error 不能代替普通应用实测。结果面板给出全部计数；整组超过 64 项只展示前 64 个逐项结果，需刷新完整列表了解当前状态。

**草稿与失败处理：** 编辑内容存入应用私有、有容量限制的草稿文件，输入 Unicode/末尾空格按原样保留；超长字段显示错误且禁止提交。刷新不覆盖草稿，外部版本变化必须选择“使用当前保存值”或“保留我的输入用于此版本”。定义被删除时草稿保留，不自动重新创建。保存失败或未知保留输入；旧操作完成仅清理完全一致的提交稿，不删除后来的修改。Activity 重建继续消费当前进程的操作。进程重建后从私有检查点恢复操作 ID，在“操作历史”显式查询命令摘要和留存资源回执；不会自动继续未完成批量，也不会根据历史结果清除草稿。

专用原生通道验证结构化参数后直接执行固定 ksud，不经过 shell；精确 status 不启动 daemon；默认定义变更使用 prepare/execute 预约协议，execute 只向已经运行的 daemon 发送一次，不冷启动、不自动重试。原路径兼容入口仍使用原有普通调用链。单次 JNI 等待预算 10 秒，子进程通信最多 8 秒；不保证后台 daemon 命令在超时后停止。分页在每次请求前后检查 30 秒预算、4096 条及累计 8 MiB 回包，并在结束后再读取一个空页核对保存版本；不能完成时保留部分结果且关闭修改。批量在每项前检查 30 秒预算，当前调用可能继续到自己的边界，不能称为严格 30 秒全链取消。

Manager 先取得唯一 operation ID，再确认应用私有检查点（文件同步、原子替换、目录同步与读回），成功后才能 execute。检查点未确认不发送修改；收到结果后写回本地，失败仍保留原 ID 并报告未知。“操作历史”分别显示提交时收到的资源结果、按 ID 查询的命令摘要、按 ID 查询的留存资源回执。参考[按 ID 恢复资源结果](sumh-runtime-state.md#按-id-恢复资源结果)。超时后不自动重发，不按最新同名历史认领。支持性未知或读取失败不会自动切换旧列表，以免让停用项消失。本地跟踪最多 16 条、1 MiB，容量满时只自动淘汰收到明确成功资源回包的记录；未确定或仅恢复的记录须审查后显式移除。移除本地关联不取消命令、不撤销规则、不删除服务端历史。未来格式或损坏文件禁止覆盖，保留文件排查。

**撤销：** 停用/启用互为逆操作；元数据用当前 revision 显式恢复。已有稳定定义的路径只读，改路径需明确新建并核对新定义后再删除旧定义；新定义使用新 ID。兼容工具仅返回启用路径，路径编辑不保留原 ID/元数据，不能替代此流程。复制选中路径是文本快捷操作；完整 ID、enabled 和元数据使用下面的定义文件交换入口。所有操作只作用于用户定义，不以全局 clear 撤销模块规则。

## 完整定义文件交换

第十六批提供当前可用的 Manager 导入/导出和精确 CLI。导出只包含持久定义，可以在内核能力不可用时进行；前提是控制器支持对应格式、保存文件可读且跨页版本一致。缺少 boot ID 不阻止配置导出，但会阻止修改预检。导入生效仍要求受管用户隐藏能力、已知 boot ID 和当前配置版本，即使新增定义选择停用，也不能绕过能力检查。Manager 逐项协商 `hide_definition_exchange_schema:1`、`hide_definition_export_page_schema:1` 和 `hide_definition_import_schema:1`，不会仅凭总协议版本猜测支持情况。

### 文件格式与容量

完整导出和选中导出使用同一种 UTF-8 JSON：

```json
{
  "schema_version": 1,
  "kind": "sumh_user_hide_definitions",
  "rules": [
    {
      "id": "0123456789abcdef0123456789abcdef",
      "path": "/data/local/tmp/sumh-example/target",
      "enabled": false,
      "name": "测试目标",
      "note": "仅用于合成用例",
      "group": "测试组"
    }
  ]
}
```

示例 ID 和路径仅用于说明格式；实际备份保留导出的稳定 ID。根对象恰好包含 `schema_version`、`kind`、`rules`，每条恰好包含六个定义字段，均为必填；`enabled` 必须是布尔值，其他五项是字符串。不能添加运行 inode、rule ID、generation、boot marker、操作回执或授权信息。选中范围及导出 revision 保留在 Manager 的本地快照中，不写入可重放文件。空 `rules` 代表空选择，导入时不删除已有定义。

文件最多 **4 MiB + 256 字节**，最多 **4096 条**；转换为控制器规范编码后的持久配置仍不得超过 **4 MiB**。不能用额外格式开销扩大配置容量。路径最多 4095 个 UTF-8 字节，name/group 各最多 128 字节，note 最多 1024 字节。拒绝 NUL、非法 UTF-8、重复 JSON 键、未知字段、重复 ID/精确路径和未来格式，保留合法 Unicode、换行、制表符与末尾空格；不做 trim、路径规范化或分区别名合并。旧字符串数组和逐行路径文本须使用原路径兼容工具，完整定义导入不会猜测旧格式。

### Manager 导出、预检与提交

1. 用户隐藏的默认定义列表→导入导出菜单→“导出全部定义”，或先多选再“导出所选”。导出包含启用和停用项；选中导出会重新读取完整保存集合并核对所有选中 ID，缺失时拒绝导出，不静默缩减范围。文件选择器打开前已固定内容快照，后来改变选择不会改写该快照。
2. 选择“导入／预检定义”→“选择 JSON 文件”；小文档也可用“粘贴 JSON 文本”，文本入口上限 **64 KiB**。校验通过后保存为应用私有的未应用草稿，保留原始文件内容和 enabled 意图；此时不修改控制器定义或内核。无效文件不会替换已有草稿。
3. 点击“读取当前定义并预检”，查看已保存、导入及拟采用的路径、ID、启用状态和元数据。默认**新定义停用，已有定义保持原启用状态**。明确勾选“采用导入的启用状态”才会按文件的 enabled 值启用或停用目标；审查启用/停用数量。选择“保留已有定义”会保留该条全部字段，不受此开关影响。
4. 逐条处理下表冲突，再重新预检。全部候选、顺序执行中的每个中间配置和每条请求都先检查容量；拟启用路径的末级为空、`.`、`..` 或超过 255 字节会阻止提交。路径尚未出现本身不构成拒绝条件；预检不证明别名关系或应用实际可见性。
5. 预检通过后点击“提交下一组”。每组最多 **16 条实际变更**，逐条经操作预约和持久检查点提交，只有匹配 ID、boot 和前一 revision 的成功资源回执才推进版本。到达 **30 秒**后不再开始下一条；已经发出的调用可能继续至自身期限。“停止”同样只影响后续项。
6. 检查已尝试、确认成功和未尝试数量，刷新定义/注册状态。还有剩余项时，必须再次点击“读取当前定义并预检”，再明确提交下一组；不是自动续传。已完成且与本次有效策略一致的条目成为无变更项。整个文件和跨条内核同步不构成全局原子事务。

| 冲突情况 | 可选择的行为 |
| --- | --- |
| 新 ID、新路径 | 默认纳入；也可跳过。新定义默认停用。 |
| 同 ID、同路径，拟采用字段相同 | 无需重复修改；也可跳过。 |
| 同 ID、同路径，内容不同 | 保留已有全部字段、采用导入值，或跳过。 |
| 同路径、不同 ID | 保留已有定义、采用导入值并保留本地 ID，或跳过。 |
| 同 ID、不同路径 | 明确生成新稳定 ID 后新增，或跳过；不改变旧 ID 对应的路径。生成的 ID 随选择保存。 |
| ID 与路径分别指向两条已有定义 | 普通交叉冲突只可跳过，不能覆盖任一侧。之前明确生成的新 ID 若在重新预检时能证明其全部有效字段已完全匹配，可识别为已完成的无变更项；字段不匹配仍阻止修改。 |

这里只提供**合并**，未导入的已有定义始终保留，没有整份 Replace/清空语义。草稿输入、启用策略、冲突选择、配置 revision 或 boot 变化都会使预检确认失效。再次打开或进程重建后不恢复批准状态、不执行旧计划；原始草稿和选择在成功、失败、部分完成后均保留。关闭窗口不会删除草稿，重新导入另一份有效文档才会替换本地输入。

### 失败、恢复与撤销

文件读取或导出失败时检查错误；导出目标文件可能不完整，不能作为有效备份。旧文件选择回调绑定原草稿版本或固定导出令牌，不会覆盖后来修改的草稿，也不会导出更新后的选择。应用私有草稿/快照损坏或格式较新时保留文件并拒绝覆盖。页面重建不代表修改已取消，需检查操作历史。

提交失败、部分完成或结果未知立即停止后续项，先按原 operation ID 查询[留存资源结果](sumh-runtime-state.md#按-id-恢复资源结果)，再读取完整保存定义和运行注册。历史已淘汰或回执不可用不证明没有执行，不能用新 ID 自动重放。再次预检只重新比较当前状态，不自动继续执行；当前界面结果和近期 16 条操作记录也不是覆盖 4096 条的永久导入审计。

仅导入草稿或只读导出无需撤销控制器状态。已应用后，用导入前的完整备份重新导入并审查差异；如需恢复旧 enabled，明确选择采用备份的启用状态。合并恢复**不会删除本次新增定义**，须根据本次结果确认这些稳定 ID，再逐条删除或停用。新 ID 的分配不会因重新导入自动撤销。配置恢复、运行恢复和普通应用实测分别检查，不用全局 clear 清理模块 HIDE 或其他资源。

### 精确 CLI 与脚本接口

下列查询已经实现，必须用精确本地入口，不通过 `daemon call` 或全局选项包装：

```sh
# 一次输出整个可移植定义 JSON；检查退出码后才把文件视为完整备份
/data/adb/ksud sumhp hide export
# 只读取持久定义，不采样内核注册；可供程序分页
/data/adb/ksud sumhp hide definitions
# revision 与 next_cursor 来自同一轮成功回包
/data/adb/ksud sumhp hide definitions "$revision" "$next_cursor"
```

`definitions` 每页最多 64 条，并按编码后大小缩减至小于 56 KiB，resource 为 `user_hide_definition_export_page`。检查 revision、boot_id、source_schema、count、cursor 连续性及 at_end；结束后用总 count 再请求一个空页复核版本。任一页失败或版本变化都不能把已取得的部分条目当作完整导出。该入口和整份 `export` 不启动 daemon、不迁移、不恢复、不访问内核；文件未知、损坏或不可读时失败。`export` 只有完整文件形式，没有当前可执行的 selected CLI 参数；选中导出使用 Manager。

单条条件写入 `hide import-id <id> <expected-revision> <JSON-fields>` 也已经实现。payload 恰好是 `path`、`enabled`、`name`、`note`、`group`、`expect` 六项；`expect:"absent"` 要求 ID 和精确路径均未被使用，`expect:"same_identity"` 要求已有 ID 与原路径同时匹配。它不是整份导入命令，不接受可移植文件直接作为 payload；每次只追加一条或原位替换该条字段。

脚本使用 JSON 序列化库构造参数，把用户路径作为数据，按[提交前取得操作 ID](sumh-runtime-state.md#提交前取得操作-id)的文件/stdin 流程 prepare、保存 ID、execute。结构示例如下；ID、revision 和路径须来自已审查的实际定义，示例不能原样提交：

```json
{
  "schema_version": 1,
  "args": [
    "hide", "import-id",
    "替换为32位小写十六进制稳定ID",
    "替换为最新revision",
    "{\"path\":\"/data/local/tmp/sumh-example/target\",\"enabled\":false,\"name\":\"测试目标\",\"note\":\"\",\"group\":\"测试组\",\"expect\":\"absent\"}"
  ]
}
```

每条输入仍受 48 KiB 与外层 64 KiB 编码限制，不把整个 4 MiB 文件塞入 IPC。Manager 的预约执行只向已运行 daemon 发送一次，不自动启动或重发；原始公开 `hide import-id` 和直接隐藏变更通道仍走普通 daemon 分派，端点不可用时可能启动 daemon 并触发原有恢复流程。脚本不能把这两种入口的行为混为一谈。成功回执仍只证明该用户条目的注册成员关系；保存后内核失败会报告 partial，未知结果先查询，不能按成功或未执行推断。

## 先读取状态和版本

在已授权的 root shell 中执行精确命令：

```sh
/data/adb/ksud sumhp hide status
```

该入口直接读取定义和采样内核登记，不启动 daemon、不恢复、不规范化、不迁移文件。不要通过 `daemon call` 或全局 verbose 包装它。输出为 schema 1，包含 `revision`、`boot_id`、`source_schema`、总 `count`、本页 `items`、`next_cursor`、`at_end` 和 `complete`。`revision` 是整个保存文件的原始字节摘要，格式为 `sha256-v1:` 加 64 位小写十六进制。

每页最多 16 条，并根据 JSON 转义后的大小进一步缩减，完整回包小于 56 KiB。若 `at_end:false`，保留首次 revision，用本页 next_cursor 继续：

```sh
# 变量来自成功的前页回包；不是任意填写的版本号
/data/adb/ksud sumhp hide status "$revision" "$next_cursor"
```

跨页保持同一 revision；配置变化会拒绝分页，需要重新读取。`complete:true` 只表示从第 0 条开始的一页已经包含全部定义；多页调用者须核对 count、cursor 连续推进和最终 at_end。不得把一页缺少某条定义解释为该定义已删除。每页内核信息为 `per_rule_sampled`，不承诺跨页运行快照一致。

| state | 含义与后续处理 |
| --- | --- |
| `unknown` | 运行查询不可用；保留 enabled 和保存定义，不据此删除。 |
| `disabled` | 保存为停用，采样未见用户注册。 |
| `disabled_pending_removal` | 已停用但仍有用户注册；检查最近结果，确认后可重新执行 disable。 |
| `unregistered` | 已启用但未见用户注册；检查能力、全局状态和最近操作，再决定是否 retry。 |
| `globally_suspended` | 运行条目随全局关闭暂停，不能通过修改单条 management 恢复。 |
| `bound`、`pending`、`binding_error` | 已注册的绑定状态；结合 runtime 的 binding、errno 和 generation 判断。 |

`runtime_query` 单独区分 observed、unsupported、unavailable。保存文件损坏、未来格式、读取失败或读取期间变化会返回非零和不完整结果；不会返回一个看似正常的空列表。

## 新建、注释、分组与启停

**目的与条件：** 对自己的合成测试路径保留可重复启停的定义，并按用途分组。先读取完整状态和最新 revision；新建/启停需受管能力。示例 `/data/local/tmp/sumh-example/target` 是占位测试路径。

```sh
# 先保存为停用；此操作同样要求受管能力
/data/adb/ksud sumhp hide create "$revision" \
  '{"path":"/data/local/tmp/sumh-example/target","enabled":false,"name":"测试目标","note":"仅用于合成用例","group":"测试组"}'
/data/adb/ksud sumhp hide status
```

从最新查询取得新定义的 `$definition_id` 和 `$revision`。后续**每次修改前都使用最新版本**，不要把一组旧版本命令连续重放：

```sh
# 修改名称/备注/分组，可只提供其中一个字段；不支持在 annotate 中修改 path 或 enabled
/data/adb/ksud sumhp hide annotate "$definition_id" "$revision" '{"note":"更新说明"}'
# 查询新版本后，选择下面需要的一项
/data/adb/ksud sumhp hide enable "$definition_id" "$revision"
/data/adb/ksud sumhp hide disable "$definition_id" "$revision"
/data/adb/ksud sumhp hide enable-group '测试组' "$revision"
/data/adb/ksud sumhp hide disable-group '测试组' "$revision"
/data/adb/ksud sumhp hide retry "$definition_id" "$revision"
```

**期望观察：** 启用后注册可能是 bound、pending 或 binding_error；停用后定义仍存在、enabled=false，用户注册消失。按组操作保存整个目标配置，再同步选中条目；不承诺多条内核变更原子完成。自动恢复与修改使用同一协作锁，恢复仅投影 enabled 路径；停用定义不会在 daemon/设备重启或后续绑定事件中被控制器重新添加。真实重启/并发内核验收仍待完成。

**失败处理：** revision 冲突、锁忙、能力未知或保存前运行查询失败时停止，重新查询后再决策。保存确认后内核失败保留已保存的启用状态，并返回部分结果；不自动回滚配置，也不盲目重放。结果未知先查询定义、运行状态和[操作历史](sumh-runtime-state.md#近期操作历史与等待)。等待绑定不需要连续重复重试。

**撤销：** enable/disable 互为定义启停操作，都需要最新 revision。恢复原名称、备注、分组需显式 annotate。需要删除定义时，先记录其全部字段，再执行 `hide remove-id "$definition_id" "$revision"`；重新 create 会分配新 ID。启用或删除都不通过全局 clear 撤销其他规则。

## 结果、脚本与容量

新定义变更输出 schema 1、resource=`user_hide_mutation`。`saved` 表示本次是否确认目标定义已保存，未知时为 null；`revision` 是确认的保存版本，`previous_revision` 是起始版本，另有 boot_id。状态包括 rejected、not_saved、outcome_unknown、saved/unchanged、applied、partial；元数据修改不执行内核动作。

`applied` 在这里仅表示选中条目的注册成员关系符合定义，**不是观察者视图已验证**。回包固定 `runtime_verified:false`，并声明 `verification_scope:registered_membership_not_observer_visibility`。pending 或 binding_error 可与成员关系成功同时出现，具体绑定信息位于每条 runtime。失败的内核调用即使读回成员关系匹配，也保留失败/部分状态。

`affected_count`、`confirmed_count`、`failed_count`、`unknown_count` 汇总整个操作；最多返回 64 个逐项结果，超过时 `items_complete:false`，须再分页查询。逐项结果只用稳定 ID 关联，不回显大段路径和备注。元数据操作只报告保存结果，成员关系统计不表示进行了运行验证。配置最多 4096 条、编码后 4 MiB；路径少于 4096 个 UTF-8 字节，name/group 各最多 128 字节，note 最多 1024 字节。拒绝 NUL、未知字段、重复 JSON 键、重复 ID/精确路径和未来格式。保留合法 Unicode、末尾空格及路径入口允许的换行字节。

需要提交前取得 operation ID 时，使用[预登记执行](sumh-runtime-state.md#提交前取得操作-id)。输入示例：

```json
{"schema_version":1,"args":["hide","disable","替换为稳定定义ID","替换为最新revision"]}
```

将占位符替换为查询值后，保存为输入文件或通过 stdin 交给 operation prepare/execute；输入限制继续使用 48 KiB 和外层 64 KiB，args 不作为 shell 执行。资源结果在操作回包 stdout 中，操作身份在外层结果中。普通变更仍走 daemon，其冷启动可能按原策略恢复；精确 hide status 不会。预约不固定配置文件；实际执行发现 revision 已变化会拒绝目标修改。

旧 `hide add/remove/list` 保留路径接口。add 已保存的启用路径仍触发重新绑定；add 不会隐式启用已停用定义。新增 `hide retry-path <绝对路径>` 供旧路径工作流使用：控制器在锁内确认该路径仍已保存且启用，才执行注册/重试；已删除或停用的路径返回失败。Manager 的路径兼容工具使用该入口；新的定义列表按稳定 ID 使用 retry。旧 list/兼容工具只包含 enabled 路径，停用定义使用新列表或本页 status 管理。

Manager 路径兼容工具的“更改路径”仍由“添加新路径、删除原路径”组成，会创建新的稳定 ID，且不转移原定义的名称、备注和分组。对已有元数据的定义，先保留全部字段，再明确新建并确认新定义、最后删除原定义；不要把旧界面的路径编辑当作元数据保留式修改。新定义界面的路径保持只读，元数据可编辑。

## 旧格式迁移与恢复边界

旧字符串数组按只读方式解释为 enabled=true、空元数据的稳定定义；相同精确路径合并，保留首次顺序。稳定 ID 由版本域和原路径生成，查询和启动恢复不重写旧文件。首次显式修改前，将原始字节耐久备份为同目录 `user_hide_rules.legacy.bak`，确认后才写入 schema 1 对象。已有备份内容不同则拒绝覆盖，需先调查文件来源。

保存先校验容量/格式、核对当前源版本，再提交和读回。替换已发生但耐久性/读回未确认时返回 outcome_unknown，并停止本次内核同步；后续正常启动恢复仍使用能读到的有效定义。文件变更、跨内核同步和最终操作历史不是一个全局原子事务。

未来格式、损坏或读取失败保留文件并拒绝破坏性保存。迁移备份是迁移时的原始状态，不能代表之后全部修改；不要直接拿它覆盖当前文件作为通用撤销。当前没有自动降级转换命令，旧二进制可能不认识 schema 1；降级前需在维护流程中显式转换并分别保留当前完整定义和原始备份，确认如何处理 disabled/元数据，不能将“旧格式读取失败”当作空配置继续保存。正常操作的撤销优先使用上述 revision 条件命令。
