## 第一轮：基本流程

建议仅新建带 `test-20261021-` 前缀的方案；名称可用“方案测试 中文 😀”，备注包含尾部空格。每次写入后按页面提示“查询当前状态 → 确认已查看”，再发起下一次写入。这个核对步骤在成功保存后也可能出现，不是自动重试。

| 顺序 | 操作 | 预期及失败处理 |
| --- | --- | --- |
| 1 | 进入配置方案页，手动读取 | 页面打开不自动执行后端操作；支持时显示库容量及条目。不支持／读取失败时保留提示，不能把失败当成空库。先核对授权和控制器版本。 |
| 2 | 使用新 ID 捕获，取消一次确认，再确认保存 | 取消不写入；确认后生成未启用方案，包含全部四资源。现有活动配置与内核集合不因捕获变化。出现未知结果先核对当前目标，勿重复提交。 |
| 3 | 打开新方案，分别选择 settings、modules、user_hide、maps 比较 | 差异按资源显示，资源选择只控制比较范围；结果不宣称可以激活。来源配置未变时资源差异应为空。 |
| 4 | 复制，编辑副本名称并确认；再给副本改名 | 对话框可滚动、编辑和确认，无卡住；副本获得不同 ID，改名保留副本 ID；原方案不受影响。 |
| 5 | 导出副本；先取消保存位置，再重试并保存 | 固定导出卡片显示自己的 ID／版本；取消保留内容；重试保存同一份文档。用系统文件管理器确认文件存在且非空。 |
| 6 | 选择刚导出的文件，手动预检，以另一个新 ID 导入 | 选择文件只保存本机草稿；没有预检不能导入；导入仍保留全部四资源，整体未启用。用详情与原方案比较资源。 |
| 7 | 删除测试副本，先取消再确认 | 取消保留条目；确认仅删除该方案。核对当前缺失后继续；缺失不能证明过去某次中断的删除一定成功。 |

## 第二轮：边界与恢复

| 操作 | 预期 |
| --- | --- |
| 先填草稿，再刷新／切后台／旋转屏幕 | 当前草稿保留；忙碌时不重复发起写入，完成后能查看结果。 |
| 将导出文件复制为测试文件，故意破坏 JSON，再选择 | 拒绝该文件，保留之前有效的导入草稿。不要直接编辑活动配置或方案库。 |
| 使用已有方案 ID 再捕获／导入 | 拒绝覆盖，旧条目保持；核对后换新 ID。 |
| 选中方案后，通过另一明确操作改变方案库，再回到旧详情操作 | 返回冲突或使详情失效，要求重新读取并审查；不能默默用新内容替换已审查内容。 |
| 导出保存失败后重进页面，重试固定导出 | 不自动打开文件选择器；显式重试可使用原固定 ID／版本，无须重新获取后端文档。 |
| 写入期间手动强制停止 Manager，再打开 | 不自动重放；存在待核对记录时先查询当前目标，再明确确认。若前台未赶上保存检查点，需记录这一情况，不能据此推断是否保存。 |
| 出现“重新读取本机草稿”后取消，再确认 | 取消保留屏幕内容；确认重读应用私有草稿并使旧预检失效，不操作方案库。无此故障提示时无须人为损坏私有文件。 |
| 大字体、横屏、系统深浅色、键盘展开、TalkBack | 内容及取消／确认可达，字段标签和禁用状态可理解。尤其检查复制／改名表单和导入确认。 |

进程终止测试放在基本流程通过以后，仅操作测试方案。任何结果未知都先查询当前状态；没有历史回执时不要写成“确认未执行”或“确认已执行”。

## 其余 SUMH 能力的快速回归

此次方案功能不会替代各资源的验收。基础流程通过后，可从[33 个使用场景](../zh/guide/sumh-usage-scenarios.md)选择已有能力：模块路径预览／解释、用户隐藏逐条启停、Maps 预检与明确应用、Kernel Build 草稿辅助、能力中心和诊断只读查询。写入类用例仅使用自建测试目录／规则，逐项记录及撤销，不执行全局 clear。

模块、隐藏、Maps 的实际效果需要按[观察者指南](../zh/guide/sumh-observer-kit.md)分别记录普通应用、授权应用及 root 的视图；root 查询成功不能代替普通应用效果。源文件、挂载或 inode 变化后的 Maps 重应用、内核切换等复杂用例可在第一轮反馈后继续。

## 反馈与清理

每个失败记录：测试编号、操作步骤、屏幕错误码、方案 ID、库／方案 revision、是否有待核对记录、是否已查询、设备型号、Android／真实内核版本、当前 boot ID、Manager 与控制器版本，以及可复现次数。截图与日志只取需要的片段；实际方案 JSON 可能包含个人路径，分享前自行检查。

通过／失败／未执行分别记录。导出需要保留的测试方案后，只删除此次创建的测试 ID。不要清空整个方案库、用户隐藏或 Maps 集合；不卸载 Manager、不清除应用数据来“解除”待核对状态。实际运行配置的恢复按对应资源指南执行，不能用未启用方案代替。
